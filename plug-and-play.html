Plug in your data

Run the tools on your own numbers

Every tool below starts from public data. Each one also takes a company's own file: download the template on the tool's page, fill it in, and load it.

  • Nothing is uploaded. Files are read in your browser. The last file is kept in this browser only, until you choose "Back to public data".
  • CSV or JSON. Spreadsheet exports work as CSV.
  • Strict checks. A file with a problem is not used. Every problem is listed by row, so it can be fixed in one pass.
  • Your numbers are marked. Anything from your file is tagged Yours. Public numbers keep their sources.

Independent. Not affiliated with Base Power.

Market

Page: /market. Adds your own per-state metrics to the expansion score, or swaps the public Texas zone values for your own. One file holds one kind; the page tells them apart by their columns.

State metrics file: CSV with a state column (two-letter code such as TX, or the full name such as Texas) plus any number of number columns, one per metric. A header ending in (lower is better) ranks low values best; every other column ranks high values best. JSON: { "factors": [{ "key", "label", "higherIsBetter" }], "states": { "TX": { "key": value } } }; factors is optional and sets labels and direction. Download the template from the page: it lists all 51 states with two example columns left blank.

ColumnMeaningUnit
statestate code or full name, once per statetext
any other columnone of your metrics, such as install_cost_usd (lower is better), cac (lower is better), permit_days (lower is better), pipeline_homesyour own

Each metric becomes a factor in the score, ranked as a percentile across the states that have a value, the same way as the public factors. It gets its own weight slider (default 1) under Yours in Score weights, and it can color the map.

Texas zone values file: CSV with zone,usd_per_year, or JSON { "zones": [{ "zone", "usd_per_year" }] } (also accepted: { "zones": { "LZ_NORTH": 150 } }). Zone ids must match the public list of ERCOT load zones (LZ_AEN, LZ_CPS, LZ_HOUSTON, LZ_LCRA, LZ_NORTH, LZ_RAYBN, LZ_SOUTH, LZ_WEST). Trading hubs (HB_ ids) are not accepted: homes settle at load zone prices, so a hub is not a place one battery earns. Your numbers replace the public ones in "Where one battery earns most (Texas)" and are tagged Yours. The template lists every load zone with its public value.

How the public zone values are made: one Base Core (20 kW / 39.2 kWh, 88% round trip, 20% reserve) on one fixed daily clock, charge 10 AM to 2 PM and discharge 7 to 9 PM Central, at each load zone's real-time price over the latest 12 complete months. About 31 kWh is usable, so it sells 20 kWh from 7 to 8 PM and about 9 kWh from 8 to 9 PM. The clock was chosen from how ERCOT prices move (cheap midday solar, a net-load peak after sunset), not by searching the prices it is scored on. Energy arbitrage only. Method and numbers: /data/zone-value.json.

Rules: a blank cell means no value. For a metric, that state is scored on the other factors, the same as missing public data, and a warning lists the states. For a zone, the public value stays. Unknown states or zones, a state or zone listed twice, non-numbers (named by row and column), negative zone values, and a file with no number columns stop the load and are listed by row. "Back to public data" removes your file.

Example:

state,install_cost_usd (lower is better),permit_days (lower is better),pipeline_homes
TX,11500,9,4200
FL,13200,21,800
Georgia,12800,14,350

Pitch

Page: /pitch. Swaps Base's public claims and this page's assumptions for your own offer terms, and marks the utilities on your own target list.

File: one CSV or JSON file holds either part, or both. In a CSV, a row with a key is an offer term and a row with a utility is a target; a row with both, or neither, is an error. Extra columns such as unit, label and public_basis are ignored. Each file you load replaces the last one, so keep terms and targets in the same file to use both. Download the templates from the page: the offer terms template lists every key with its public value and already has the target columns, and the target list template starts with the public top 5 to call in the selected state.

JSON shapes: { "key": value } (terms only), { "terms": { "key": value }, "targets": [{ "utility", "status", "owner", "note" }] }, or a list of row objects shaped like the CSV.

Offer terms (key,value):

Target list (utility,status,owner,note, optional state): utility is the EIA id used in the data (for example 5078-TX), the name as listed, Name, ST, or a public alias such as CoServ Electric. status is free text, for example in talks, signed or not contacted.

Rules: blank term values keep the public number. Unknown keys, non-numbers, values outside each key's range (shown in the template's min and max columns) and a low end above its high end stop the load and are listed by row. Unmatched or ambiguous utility names do not stop the load: each is listed as a warning, with the closest public name when one is near. So is an id whose state disagrees with the utility (for example 5078-TX with state IL). Number cells take plain decimals only ($, , and % are dropped); hex such as 0x10 is not a number. Keys are matched exactly, so constructor or __proto__ is an unknown key. Changed numbers are tagged Yours on the pitch and in print, and the public claim stays shown beside them. Matched utilities show their status on the pitch and go first in "Who to call first", still in public rank order; targets in other states are listed under the table. A target that is a wires-only utility (it delivers power but does not buy it, such as Oncor or ComEd) still shows, labeled Wires only and unranked.

Supply

Page: /supply. Loads your own bill of materials and shows which parts will run short. The public research stays on the page below your card.

File: CSV with one row per part, or JSON { "parts": [ { ... } ] } with the same fields (a bare array of parts also works). Download the template from the page: it has one fictional example row per category.

FieldMeaningUnit
partpart name (required)text
categorypower_electronics, bms_memory, cells, cellular, grid_equipment, labor, metals or other (required)id
supplierwho you buy it fromtext
countrywhere it ships fromtext
lead_time_weeksweeks from order to delivery, 0 to 520 (required)weeks
on_hand_weeksinventory plus open orders, in weeks of production, 0 to 520weeks
second_sourceyes or notext
tariff_pctUS tariff on this part, 0 to 500%
unit_cost_usdcost of one unit, 0 to 1,000,000$
qty_per_unithow many go into one battery, 0 to 10,000count
noteanything elsetext

Rules: gap = lead_time_weeks minus on_hand_weeks (a blank cover counts as 0). Rows are sorted by gap, biggest first. Flags: Will run short when the gap is above 0, Single source when second_source is no, Tariff 25%+ when tariff_pct is 25 or more. Tariff cost per battery adds unit_cost_usd * qty_per_unit * tariff_pct / 100 over the rows that have all three. Column names match without regard to case or surrounding spaces, so Lead_Time_Weeks works; a column the tool does not know is named in a warning and ignored. Missing required fields, unknown categories, text fields that are not text (in JSON, an object or a list; a number such as a part number is read as text), non-numbers (plain decimals only, after dropping $, , and %; 0x10 and Infinity are not numbers), negative numbers and values over the limits in the table stop the load and are listed by row. Duplicate part names load with a warning. Each row links to the public research card for its category.

Example:

Finance

Page: /finance. Swaps the public cost, tax credit, revenue and loan inputs for your own. The page is a generic model of one leased home battery, not any company's books.

File: CSV with key,value columns, or JSON { "key": value } (also accepted: { "inputs": { ... } } or [{ "key", "value" }]). Extra columns such as unit and label are ignored. Download the template from the page: it lists every key with its public value.

KeyMeaningUnit
any input key from the templatereplaces that input; must be a plain decimal number within the input's min and max (whole numbers for lifeYears, tenorYears and fleetCount)as listed
itcPctinvestment tax credit (IRC 48E), percent of installed cost, 0 to 70; treated as sold for cash at face value when the battery goes into service%
revenueCasetoll, merchant or stackedtext
zoneERCOT load zone for the arbitrage valuezone id
arbPerYearyour own arbitrage value; replaces the zone$ per battery per year

Rules: blank values keep the public number (a warning says so). Unknown keys (including names such as __proto__ or constructor), non-numbers, hex such as 0x10, and out-of-range values stop the load and are listed by row. Typing in the page's fields follows the same rules: an invalid field shows an error and the results wait until it is fixed. Changed inputs are tagged Yours, and their notes show the public value they replaced.

Launch

Page: /launch. Swaps the public launch steps for your own steps, durations and email-tennis costs.

File: CSV with one row per step, or JSON { "paths": { "retail": { "steps": [ ... ] } }, "tennis": [ ... ] } (a partial copy of /data/launch-steps.json). Download the template from the page: it lists the selected path's steps for the selected state, with each step's round cost.

ColumnMeaningUnit
pathretail or utilitytext
idstep id, unique within the path; letters, digits, _, ., -text
namestep name shown on the pagetext
ownerwho does it (optional)text
lowfast case, 0 to 260weeks
highslow case, at least low, at most 260weeks
depends_onstep ids this step waits for, separated by ;ids
round_weekscost of one extra back-and-forth round for this step (optional)weeks
noteanything you want shown under the step (optional)text

In JSON, depends_on is a list, and tennis entries are { "step", "round_weeks", "with", "bounce", "fix" }.

Rules: a path in your file replaces that path's steps in every state, and public state rules do not apply to it. A path not in your file keeps the public steps. A step's round_weeks replaces its email-tennis cost; a step without one keeps the public cost for the same id, if there is one. Unknown paths, missing ids or names, ids reserved on every JavaScript object (__proto__, constructor, prototype, toString and the like), text fields that are not text (in JSON, an object or a list), non-numbers (durations are plain decimals: 0x10 and Infinity are not numbers), negative or over-260 durations, high below low, duplicate ids, unknown depends_on ids, cycles and bad round_weeks stop the load and are listed by row. A missing owner, or no first_installs step, gives a warning. Steps from your file are tagged Yours.

Plug in your data

The home battery tool, and the file formats kept with the code

The public tool is the home battery ROI page. It does not take a spreadsheet. The sections after it document file formats for code that is still in the repo.

  • Nothing is uploaded. Files are read in your browser. The last file is kept in this browser only, until you choose "Back to public data".
  • CSV or JSON. Spreadsheet exports work as CSV.
  • Strict checks. A file with a problem is not used. Every problem is listed by row, so it can be fixed in one pass.
  • Your numbers are marked. Anything from your file is tagged Yours. Public numbers keep their sources.

Independent. Not affiliated with Base Power.

Home battery ROI

Page: /. One Texas home. The same code answers POST /api/v1/home.

Send JSON. query is a ZIP (77002), a place (Houston), or a street address that contains a ZIP. preset is bungalow, suburban or ranch. revenueCase is merchant, toll or stacked. fleetCount is the fleet roll-up. zone is optional: send it when the ZIP is served by Oncor or TNMP, or when no load zone is on file.

Suburban annual use is the 2024 Texas residential average, 1,097 kWh a month. Bungalow (9,000 kWh) and ranch (18,000 kWh) are labeled assumptions. Earnings use data/zone-value.json (real-time load-zone prices, 2025-10-01 to 2026-10-01, fixed clock). Debt, payback, simple ROI and IRR use finance-core.js. Backup is $0 of cash flow: the replay already holds a 20% reserve, and no outage dollar is in the file.

A ZIP that does not pick one zone returns needsZone: true and does not invent a zone.

Example:

{ "query": "77002", "preset": "suburban", "revenueCase": "merchant" }

Market

Page: /market. Adds your own per-state metrics to the expansion score, or swaps the public Texas zone values for your own. One file holds one kind; the page tells them apart by their columns.

State metrics file: CSV with a state column (two-letter code such as TX, or the full name such as Texas) plus any number of number columns, one per metric. A header ending in (lower is better) ranks low values best; every other column ranks high values best. JSON: { "factors": [{ "key", "label", "higherIsBetter" }], "states": { "TX": { "key": value } } }; factors is optional and sets labels and direction; when sent it must be a list, and higherIsBetter must be true or false (or the text "true" or "false"), or left out for higher is better. "no", 0 or null is an error, not a silent "higher is better". Download the template from the page: it lists all 51 states with two example columns left blank.

ColumnMeaningUnit
statestate code or full name, once per statetext
any other columnone of your metrics, such as install_cost_usd (lower is better), cac (lower is better), permit_days (lower is better), pipeline_homesyour own

Each metric becomes a factor in the score, ranked as a percentile across the states that have a value, the same way as the public factors. It gets its own weight slider (default 1) under Yours in Score weights, and it can color the map.

At least 5 states per metric. A percentile rank among very few values means nothing: one state alone would get full marks, and with two the lower one would get 0 and score below states with no data at all. A metric with values for fewer than 5 states is left out of the score, with a warning naming it. Five gives ranks in steps of a quarter, the same quarters the map legend colors by. If no metric in the file reaches 5 states, the file does not load.

Texas zone values file: CSV with zone,usd_per_year, or JSON { "zones": [{ "zone", "usd_per_year" }] } (also accepted: { "zones": { "LZ_NORTH": 150 } }). Zone ids must match the public list of ERCOT load zones (LZ_AEN, LZ_CPS, LZ_HOUSTON, LZ_LCRA, LZ_NORTH, LZ_RAYBN, LZ_SOUTH, LZ_WEST), in any case (lz_north works, the same as on /finance). Each value is 0 to 100,000 $ per battery per year, the same cap /finance puts on arbPerYear. Trading hubs (HB_ ids) are not accepted: homes settle at load zone prices, so a hub is not a place one battery earns. Your numbers replace the public ones in "Where one battery earns most (Texas)" and are tagged Yours. The template lists every load zone with its public value.

How the public zone values are made: one Base Core (20 kW / 39.2 kWh, 88% round trip, 20% reserve) on one fixed daily clock, charge 10 AM to 2 PM and discharge 7 to 9 PM Central, at each load zone's real-time price over the latest 12 complete months. About 31 kWh is usable, so it sells 20 kWh from 7 to 8 PM and about 9 kWh from 8 to 9 PM. The clock was chosen from how ERCOT prices move (cheap midday solar, a net-load peak after sunset), not by searching the prices it is scored on. Energy arbitrage only. Method and numbers: /data/zone-value.json.

Rules: a blank cell means no value. For a metric, that state is scored on the other factors, the same as missing public data, and a warning lists the states. For a zone, the public value stays. A zone file's columns other than zone and usd_per_year are ignored with a warning. Unknown states or zones, a state or zone listed twice, a column name written twice (or two names that match in any case), more than 50 metric columns, non-numbers (named by row and column; a comma is only a thousands separator, so 3,5 is an error that says to use a dot), zone values below 0 or above 100,000, and a file with no number columns stop the load and are listed by row. A spreadsheet, zip or image renamed .csv is refused as a binary file; a CSV saved as cp1252 or Latin-1 (Excel's plain "CSV" on Windows) is refused with a message to save it as "CSV UTF-8"; UTF-16 with a byte order mark is read. "Back to public data" removes your file.

Public factors you rank against: the retail-choice path is a per-state legal flag (1 where state law opens residential retail choice today, each state sourced in its detail and checked 2026-11-04), not a delivery-share cut. The ERCOT congestion section is resource-node basis, context on grid congestion, not battery value: homes settle at load zone prices, which is what your zone values file replaces.

Link to a state: /market?state=Texas, ?state=TX and ?state=tx all open Texas. With every weight at 0 no state has a score, so the detail shows no rank.

Pitch

Page: /pitch. Swaps Base's public claims and this page's assumptions for your own offer terms, and marks the utilities on your own target list.

File: one CSV or JSON file holds either part, or both. In a CSV, a row with a key is an offer term and a row with a utility is a target; a row with both, or neither, is an error. Column names are matched in any case, with spaces trimmed (Utility and STATUS work); a column written twice (key and Key) is an error, reported once. A spreadsheet, zip or image renamed .csv is refused as a binary file; a CSV saved as cp1252 or Latin-1 (Excel's plain "CSV" on Windows) is refused with a message to save it as "CSV UTF-8"; UTF-16 with a byte order mark is read. Template columns such as unit, label and public_basis are ignored; any other column is ignored with a warning. Each file you load replaces the last one, so keep terms and targets in the same file to use both. Download the templates from the page: the offer terms template lists every key with its public value and already has the target columns, and the target list template starts with the public top 5 to call in the selected state.

JSON shapes: { "key": value } (terms only), { "terms": { "key": value }, "targets": [{ "utility", "status", "owner", "note" }] }, or a list of row objects shaped like the CSV.

Target list (utility,status,owner,note, optional state): utility is the EIA id used in the data (for example 5078-TX), the name as listed, Name, ST, a public alias such as CoServ Electric, a common short name such as Oncor or ComEd, or the name without Co, Inc or LLC, in any case. The same matcher runs in the page's utility box and the API. status is free text, for example in talks, signed or not contacted. Every text cell must be text: in a JSON file, a list or object is an error naming the row. A list holds at most 500 targets, and a utility name at most 200 characters.

Rules: blank term values keep the public number. Unknown keys (the message names the closest key), a key on two rows, one utility on two target rows (by any of its names), non-numbers, values outside each key's range (shown in the template's min and max columns), a termYears that is not a whole number, and a low end above its high end stop the load and are listed by row. Target names follow the same rule as keys: a name that matches no utility, several utilities, or a utility in another state (for example 5078-TX with state IL) stops the load, named by row. The "Did you mean" comes from the row's own state, else the state of the pitch on screen, and from another state only for a near-exact name, so a Texas pitch never suggests a far-off Michigan utility. Number cells take plain decimals only ($ and % are dropped, and a comma only as a thousands separator: 3,5 is an error that says to use a dot); hex such as 0x10 is not a number. Fullwidth letters and digits read as plain ones, in the utility box and the API alike. Keys match in any case (tollperkwyear is tollPerKwYear); constructor or __proto__ is an unknown key. Changed numbers are tagged Yours on the pitch and in print, and the public claim stays shown beside them. Matched utilities show their status on the pitch and go first in "Who to call first", still in public rank order; targets in other states are listed under the table. A target that is a wires-only utility (it delivers power but does not buy it, such as Oncor or PECO) still shows, labeled Wires only and unranked. ComEd and Ameren Illinois are not wires-only: Illinois law requires each to file a virtual power plant tariff, so they are ranked. memberReservePct also sets the reserve in the capacity illustration (otherwise 20% is assumed). That illustration fits the utility's market: an accredited MW at NYISO's 2-hour factor only in a capacity market (PJM, MISO, ISO-NE, NYISO); in ERCOT, which has no capacity accreditation, the MW the fleet could hold through a 2-hour peak (4CP and price spikes are what count there); elsewhere the same 2-hour MW, with accreditation left as a question. A target that is already a Base partner (for example CoServ, Austin Energy or GVEC) also shows first, labeled Already a Base partner (El Paso Electric: Runs a pilot with Base, as its own release describes it) and unranked, and its pitch is framed as expanding the existing program. The target list template starts from the public top 5 cold prospects, so it never includes a partner or a wires-only utility.

Supply

Page: /supply. Loads your own bill of materials and shows which parts will run short. The public research stays on the page below your card.

File: CSV with one row per part, or JSON { "parts": [ { ... } ] } with the same fields (a bare array of parts also works). Download the template from the page: it has one fictional example row per category.

FieldMeaningUnit
partpart name (required)text
categorypower_electronics, bms_memory, cells, cellular, grid_equipment, labor, metals or other (required)id
supplierwho you buy it fromtext
countrywhere it ships fromtext
lead_time_weeksweeks from order to delivery, 0 to 520 (required)weeks
on_hand_weeksinventory plus open orders, in weeks of production, 0 to 520weeks
second_sourceyes or notext
tariff_pctUS tariff on this part, 0 to 500%
unit_cost_usdcost of one unit, 0 to 1,000,000$
qty_per_unithow many go into one battery, 0 to 10,000count
noteanything elsetext

Rules: gap = lead_time_weeks minus on_hand_weeks (a blank cover counts as 0). Rows are sorted by gap, biggest first. Flags: Will run short when the gap is above 0, Single source when second_source is no, Tariff 25%+ when tariff_pct is 25 or more. Tariff cost per battery adds unit_cost_usd * qty_per_unit * tariff_pct / 100 over the rows that have all three. Column names match without regard to case or surrounding spaces, so Lead_Time_Weeks works; a column the tool does not know is named in a warning and ignored. A column written twice (the same name, or Lead_Time_Weeks and Lead time weeks) stops the load. A BOM checker file (part_number, description, qty, lead_time_days) stops the load with a message that points to the BOM CSV checker below. Weeks show one decimal, or more when one decimal would hide a real gap: lead 3 against cover 2.99999 reads "3 wk", "2.99999 wk" and a gap of "0.00001 wk", never "3 wk / 3 wk / Will run short". A gap that still rounds away reads "under 0.1 wk" (0.05 included), never "0 wk" or a rounded-up "0.1 wk"; a gap under a billionth of a week (float noise) is 0. A file holds at most 2,000 parts. When no row has a tariff cost, the summary names only the columns that are missing. Missing required fields, unknown categories, text fields that are not text (in JSON, an object or a list; a number such as a part number is read as text), non-numbers (plain decimals only, after dropping $ and %, with a comma only as a thousands separator: 1,200 is a number, 3,5 is an error that says to use a dot; 0x10 and Infinity are not numbers), negative numbers and values over the limits in the table stop the load and are listed by row. Duplicate part names load with a warning. Each row links to the public research card for its category. A spreadsheet, zip or image renamed .csv is refused as a binary file; a CSV saved as cp1252 or Latin-1 (Excel's plain "CSV" on Windows) is refused with a message to save it as "CSV UTF-8"; UTF-16 with a byte order mark is read.

BOM CSV checker

A second checker on the same page, above the research. It reads a CSV in the browser and does not upload it. It is not the file above, and it is not POST /api/v1/supply: this one takes part_number, description, qty, supplier with times in days, the file above takes part, category, lead_time_weeks with times in weeks. The page says so beside the checker, and a file in the panel's format gets a message pointing to "Use your own data" at the top of the page. Missing required columns are listed in one message, a column written twice is an error, and an unknown column is ignored with a warning. The flagged-rows download puts an apostrophe in front of any text cell that starts with =, +, - or @, so a spreadsheet never runs it as a formula (every CSV the site writes does the same).

Block score is max(0, lead_time_days - on_hand_days) * (2 if single source, else 1), with ties broken by spend (qty * unit_cost_usd). The gap is how many days a reorder placed today would leave the build short. Single source means no qualified second source: listed alternates count only when alt_qualified is yes, and a row with unqualified alternates is flagged "Alternate listed, not qualified". Quantity does not raise the score, because one missing part stops the build whether you need 1 or 12. A missing lead time leaves the score unknown. Numbers are plain decimals ($ is dropped, and a comma is read only as a thousands separator: 1,200 works, 3,5 is a row error that says to use a dot); 0x10, Infinity and values over the limits in the table are row errors. A spreadsheet, zip or image renamed .csv, and a CSV that is not UTF-8, get the same messages as the panel above, never "no data rows". Rows are not merged. The sample on the page is demo data with made-up suppliers. Download gives the flagged rows only.

Finance

Page: /finance. Swaps the public cost, tax credit, revenue and loan inputs for your own. The page is a generic model of one leased home battery, not any company's books. The generic defaults come from public studies and labeled assumptions (installed cost from NREL's cost benchmark, retail and delivery prices from EIA-861, ERCOT prices); one company's published figures are an optional preset, labeled as that company's public claims, not its economics.

File: CSV with key,value columns (headers in any case, so Key,Value works), or JSON { "key": value } (also accepted: { "inputs": { ... } } or [{ "key", "value" }]). Keys match in any case (ratepct is ratePct), and so do text values (TOLL is toll, lz_north is LZ_NORTH). The template's other columns (unit, label, public_basis) are ignored; any other column is ignored with a warning that names it. Download the template from the page: it lists every key with its public value.

KeyMeaningUnit
any input key from the templatereplaces that input; must be a plain decimal number within the input's min and max (whole numbers for lifeYears, tenorYears and fleetCount)as listed

Does it pay: the page and the API show the unlevered IRR, NPV at discountPct and payback year (pay the net cost in year 0, get CFADS each year of life), and the same for the equity after loan payments. When the cash never covers the net cost, they say so plainly and list what is left out: price spikes outside the fixed 7 to 9 PM window, ancillary services, depreciation, the battery's value after its life, fee escalators and a toll.

Who keeps the arbitrage: in ERCOT, outflow from an unregistered battery of 1 MW or less is settled as a cut to the settlement load of the home's retail provider at the real-time load-zone price (Nodal Protocols 11.4.4.3 and 6.6.3.2). If your company is the home's retail provider, keep the zone value; if not, enter in arbPerYear what your contract with the provider pays, and set retailMarginMonthly to 0. In a city-utility or co-op zone (ERCOT's Non-Opt-In Entity load zones; PURA 40.051 and 41.051) there is no retail provider to keep it: the value goes to the utility, so use the toll case for a utility partnership. The arbitrage value is derived from public prices with assumptions (a fixed clock, 88% round trip, 20% reserve), not a published number. ADER is the route to ancillary services (ancPerKwYear), not needed for the energy value.

Rules: blank values keep the public number (a warning says so). A comma is allowed only as a thousands separator (1,200); 3,5 or $2,80% is a row error that says to use a dot for decimals, never 35 or 280. Unknown keys (including names such as __proto__ or constructor; the message names the closest key, such as "Did you mean ratePct?"), a key on two rows, a column written twice (reported once), a file without the key,value header row (the message shows the first line it found), a binary file such as an .xlsx (save it as CSV), non-numbers, hex such as 0x10, and out-of-range values stop the load and are listed by row. A number too large to store, such as 1e400, is reported as out of range, quoting what you wrote (a JSON number cannot be quoted back, so the message says the number is too large). Typing in the page's fields follows the same rules: an invalid field shows an error and the results wait until it is fixed. Changed inputs are tagged Yours, and their notes show the value they replaced; preset values are tagged Company claim. kw must be at least 0.1, because the 100 MW column divides by it. Loading a file keeps the zone you picked, unless the file sets zone; "Back to public data" returns to the public default zone, LZ_NORTH, so the page and POST /api/v1/finance agree on the same file.

Launch

Page: /launch. Swaps the public launch steps for your own steps, durations and email-tennis costs.

File: CSV with one row per step, or JSON { "paths": { "retail": { "steps": [ ... ] } }, "tennis": [ ... ] } (a partial copy of /data/launch-steps.json). Download the template from the page: it lists the selected path's steps for the selected state, with each step's round cost.

In JSON, depends_on is a list, and tennis entries are { "step", "round_weeks", "with", "bounce", "fix" }.

Rules: step ids and paths match in any case, like every other value in the file: depends_on A finds step a, and two ids that differ only in case are a duplicate. A path in your file replaces that path's steps in every state, and public state rules do not apply to it. A path not in your file keeps the public steps. Unknown paths, missing ids or names, ids reserved on every JavaScript object (__proto__, constructor, prototype, toString and the like), text fields that are not text (in JSON, an object or a list), non-numbers (durations are plain decimals with a dot: 1,5, 0x10 and Infinity are not numbers), negative or over-260 durations, high below low, duplicate ids, unknown depends_on ids, cycles and bad round_weeks stop the load and are listed by row. Column names match without regard to case, surrounding spaces, or spaces and hyphens for underscores (Depends On works); an unknown column is ignored with a warning, and a column written twice stops the load, with one message per column. A spreadsheet, zip or image renamed .csv is refused as a binary file; a CSV saved as cp1252 or Latin-1 (Excel's plain "CSV" on Windows) is refused with a message to save it as "CSV UTF-8"; UTF-16 with a byte order mark is read. A path may hold at most 300 steps; a longer file stops the load before any row is read. A missing owner, no first_installs step, a plan where every step is 0 weeks, or a 0-week step whose name or note does not say "milestone" gives a warning. The public license_filed step is a 0-week milestone: in Texas, market testing starts there, alongside the license review. Steps from your file are tagged Yours.

ZIP lookup

The same page looks up one US ZIP: wires utility, permit office (city or county), interconnection path, and days to a first install. POST /api/v1/zip with { "zip": "78704" } runs the same lookup. ZIP+4 works written either way, 78704-1234 or 787041234; the first five digits are used. Fullwidth digits read as plain digits, in the box and the API alike. No ZIP at all is an error that says the ZIP is required. There is no company file for it. The public file is data/zip-launch.json.

A figure that is not in the source files is the word unknown. The day total is permit_review_days + interconnection_days + crew_days, and only when each input is a calendar-day number. Coverage is Texas first (Austin, Houston, Dallas, San Antonio), plus Illinois, Georgia, and Connecticut. Oncor, CenterPoint, AEP Texas, and TNMP are not in the OpenEI ZIP file, so in Texas the wires companies inside retail choice come from Power to Choose, the PUCT plan site, ZIP by ZIP. A ZIP split between one of them and a city utility or co-op lists both. The ZIP is text: "06103", not the number 6103.
